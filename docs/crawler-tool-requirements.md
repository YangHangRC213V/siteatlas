# 可视化站点采集工具 —— 需求规格书 v0.1

## 0. 术语与歧义澄清（先定名，再谈需求）

- **「锚点」在原文里是两义混用**，必须拆开：
  - **页内锚点 / fragment**：URL 里的 `#section`，用于页内定位。
  - **链接 / link**：页面里可点的 `<a>` 元素。原文「点击锚点」「某分支的其它子节点」实指此。
  - 全文统一：**链接** = 可点元素；**锚点** = 页内 fragment。
- **网站结构本质是「有向图」，不是「树」**：同一 URL 可被多个页面指向，存在横链、回链、分页自环。界面上的树是图的**生成树投影**。原文担心的「错误归并」与「拖拽修改」正是这个本质导致的 —— 第 3 节用「自动层 + 人工修正层」建模解决。
- **「返回」有两种语义**：浏览器历史回退（有状态、有副作用）与直接导航绝对 URL（无状态、可重放）。本工具**一律用后者**，禁止依赖前进/后退栈。

## 1. 成品画像

**一句话**：一个本地运行的「网站结构采集 + 素材归档」可视化工具 —— 输入网址，自动或手动引导遍历站点，产出**可编辑的 URL 层级图谱**与**页面素材库**，并能以标准格式导出、被下游工具直接引用。

- **目标用户**：要拿到站点结构 / 页面素材去做后续分析、抽取、迁移的个人或小团队，非专业爬虫工程师。
- **典型场景**：竞品站点地图梳理；内容站归档；目标站栏目结构采集；为下游抽取/分析工具准备原始语料。
- **本期非目标**：大规模分布式抓取、代理池、强反爬/验证码对抗、公网 SaaS 化。
- **成功标准**：① 从根 URL 出发能完整覆盖同域链接；② 树视图可读、可改、可撤销；③ 导出文件能被第三个程序无人工清洗直接消费。

## 2. 命名与信息架构（为扩展留位）

产品名建议：**SiteAtlas（站点图谱采集器）**。命名原则：模块名即未来能力名，界面与代码路由一一对应。

| 模块 | 路由 | 职责 | 预留扩展位 |
|---|---|---|---|
| 站点 Sites | `/sites` | 多站点/多任务管理，收纳卡片视图 | 分组、标签、协作 |
| 采集 Crawl | `/sites/:id/crawl` | 浏览器视图 + 自动/手动采集控制台 | 定时调度、增量重爬 |
| 结构 Tree | `/sites/:id/tree` | 树视图、属性编辑、人工修正 | 差异对比、变更监控 |
| 数据 Data | `/sites/:id/data` | 素材归档、检索、预览 | 全文检索、向量化 |
| 规则 Rules | `/sites/:id/rules` | 抓取范围/过滤/解析规则 | 模板市场、AI 生成规则 |
| 导出 Export | `/sites/:id/export` | 导出预设、格式、对外 API | 数据管道、Webhook |
| 设置 Settings | `/settings` | 账号/并发/代理/凭据/外观 | 团队、配额 |

## 3. 核心数据模型（三层 + 一层人工修正）

| 层 | 实体 | 说明 |
|---|---|---|
| 站点层 | `Site` | 一个根 URL = 一棵树 = 一个站点；多个站点在 `/sites` 里呈文件夹式卡片 |
| 节点层 | `Node` | **URL 唯一实体**（非「某次访问」）。字段：`id`(永久不变)、`identityKey`(规范化指纹)、`url`(含 fragment 的完整绝对值)、`title`、`httpStatus`、`contentType`、`depth`(最小深度)、`status`(queued/crawling/ok/error/skipped/blocked/need-human)、`parents[]`、`children[]`、`createdAt` |
| 边层 | `Edge` | **一次链接关系**。字段：`fromId`、`toId`、`anchorText`、`selector`(css/xpath)、`domPath`、`rel`/`nofollow`/`target`、`fragment`、`source`(auto/manual)、`orderInPage` |
| 视图层 | `TreeView` | 生成树投影：父节点按规则确定（默认「首次发现」，可切换「最短路径」）。**它只是视图，不改数据** |
| 修正层 | `Override` | 人工操作（重挂父/改地址/改名/删除/锁定）以叠加层的形态记录，可撤销。树 = 自动投影 + 修正层合并结果 |

- 关键规则：**父节点由边决定，不由访问顺序决定** —— 这就是「不把某分支错误归并到其它锚点下」的技术保证；顺序只作为兜底推断，且必须打「推测」标记待确认。
- **URL 规范化**（去重与 identityKey 依据）：统一小写 host、补默认端口、`http→https` 可选归一、去 `www.`（可配）、去尾部 `/`、去 fragment、query 参数排序、剔除跟踪参数（`utm_*`/`sessionid`/`_ga`，黑名单可配）。**fragment 保留在 `url` 里、剔除在 `identityKey` 里**。
- **删除语义**：一律**软删除**（进回收站，可恢复），删根 = 删整站需二次确认并提示影响面。

## 4. 功能需求

### 4.1 站点与任务管理
- 输入 URL → 校验可达性/协议/是否 HTML → 创建 Site，**当前页即根节点**，标记 `depth=0`。
- `/sites` 呈现**卡片/文件夹视图**：每棵树可折叠成一个图标卡片，显示站点名、根域名、节点数、采集状态；点击卡片进入该树的树视图与详情。
- 支持站点重命名、复制、归档、删除（软删）；支持站点级备注与标签。

### 4.2 地址与导航策略（原文第 2 条）
- 内部一律存**绝对 URL**，不用相对路径：因为存在 `<base href>`、重定向、CDN/子域跳转、http↔https 混用。
- **每次抓取都是「无状态直接导航」**：新请求 = 用绝对 URL 重新发起，不依赖浏览器历史栈，保证可并发、可重放、可断点续爬。
- **由外到内**：支持带 fragment 的入口 URL 定位页内区块；页内锚点可选建为子节点（用于「板块级」采集）。
- **由内到外**：用记录的父/根绝对 URL 直接导航回跳（界面提供「回根」「回父节点」按钮），**不使用浏览器前进/后退**。
- 记录**重定向链**（301/302 全链），最终 URL 为新节点，原 URL 保留为别名/历史。

### 4.3 手动（引导式）采集
- 载体：**内嵌 Chromium（CDP 控制）**，用户真实看到网页并点击。推荐 Playwright/CDP + Tauri/Electron 外壳。
- 流程：输入 URL → 进根页 → 点「以当前页为根」→ 用户逐一点击链接，工具捕获 click → 解析被点元素 → 写入 Edge（`from` = 点击时所在页的 identityKey）→ 可选「仅记录」或「记录并展开一层」。
- **智能识别回根**：用户回到根/某已知节点时，用 `identityKey` 匹配已知节点，自动切换为该节点下的新分支记录，不新建重复节点。
- **兜底**：识别失败时允许手动「置为根/置为父节点」，并打「人工指定」标记。
- 面板：采集控制条（开始/暂停/暂停后继续/回根/展开一层/结束并保存）+ 实时待确认队列 + 当前页面身份显示。

### 4.4 自动采集引擎
- 输入有效 URL 即执行「手动流程的全部内容」，但无人值守：全量、最大深度、贪心递归（DFS 优先 + 调度队列限流）。
- **参数（全部可配、可保存为预设）**：最大深度（默认 5）、最大页数、范围策略（同域 / 同子域 / 白名单正则）、并发数（1–32）、请求间隔与抖动、超时、重试与退避、渲染方式（纯 HTTP / 强制 JS 渲染 / 自动判断）、robots.txt 遵守开关、UA、Cookie/登录态。
- **资源类型**：仅 HTML 递归；图片/PDF/音视频**记录但不递归**（可配是否下载）。
- **循环与去重三重护栏**：
  1. URL 去重（规范化 + identityKey）+ 内容去重（正文指纹）；
  2. 同一 URL 访问上限（默认 3 次）、同一路径模式（Trie 前缀）连续命中阈值即剪枝；
  3. 分页模式探测（`?page=n`/`/page/n`）设自动页数上限，防无限翻页；深度超限即停。
- **收敛与可控**：暂停/继续、断点续爬（队列持久化，重启后续跑）、实时进度（已抓/队列/失败/深度分布）、失败重试队列。
- **可选专业项**：以 `robots.txt` / `sitemap.xml` 作种子补充；登录墙/验证码检测到即把节点标为 `need-human` 并暂停该分支。

### 4.5 树视图与交互（原文第 3 条）
- **行内显示**：展开箭头 + 类型/站点图标 + **短标签**（页面标题或路径末段或用户别名）+ 子节点数 + 状态徽标（深度/已抓/失败/已修改/人工重挂）。
- **URL 默认隐藏**：仅在该节点属性面板点「修改地址」后出现可编辑输入框；行上 hover 显示 tooltip 全文。超长 URL 不参与布局。
- 属性面板（右侧抽屉）：地址、别名、标题、状态、深度、父节点列表、入链数、出链数、素材入口、修改历史。双击行打开。
- **拖拽重挂**：改变父节点，写入修正层，**打「人工修改」标记**（可一键还原为自动结果）；支持多选批量重挂。
- **撤销/重做**（含拖拽、删除、改地址、改名），快捷键 Cmd/Ctrl+Z。
- **删除**：可删根及任意子树，软删除 + 二次确认 + 影响面提示。
- **收纳**：每棵树可折叠为图标卡片，进入 `/sites` 的文件夹式视图；点开卡片再显示其树与详情。
- **检索与聚焦**：按 URL 正则 / 标题关键词 / 深度 / 状态过滤；「聚焦子树」（只看某节点以下）；面包屑回到上级。
- **性能**：虚拟滚动，万级节点展开 < 100ms；大站默认折叠，懒加载子树。

### 4.6 导出与对外引用（原文第 4 条）
- **数据分三档，分开存、按 `nodeId` 关联**：
  1. 结构数据：节点表 + 边表（URL 图）；
  2. 素材原件：`raw/`（HTML、截图、PDF…）；
  3. 解析结果：`parsed/`（正文、标题、元数据、结构化字段）。
- **导出格式**：JSON（完整图）、JSONL（流式逐节点）、CSV（节点表 / 边表）、**SQLite（推荐中间态，可直接查询）**、Excel、OPML/Markdown/Mermaid（树）、GraphML/DOT（图）。
- **目录约定 + `manifest.json` 索引**（含 `schemaVersion`、生成时间、节点计数、文件映射），使下游工具可凭约定直接读取。
- **对外引用方式**：① 文件导出；② 本地只读 HTTP JSON API（localhost，供其它工具调用）；③ 直接打开 SQLite。`nodeId` 永久稳定，跨导出、跨版本不变。
- **导出预设**：保存常用格式/字段/过滤条件，一键复用。

### 4.7 合规与礼貌（原需求未提，必补）
- 默认遵守 robots.txt；默认限速（≥1s/请求，可调）；默认并发 5；UA 可配置并默认标识为工具名。
- 本地私有：数据不出机器；登录凭据/ Cookie 加密存储，界面不回显明文。
- 首次运行给出简短合规提示（尊重目标站条款、勿高频压站）。

## 5. 界面与视觉规范（原文第 5 条）

- **风格**：清新淡雅 —— 浅色低饱和（雾蓝/薄荷绿/米白）、大留白、6–10px 圆角、1px 细边框、克制阴影；深色模式可切换；无衬线字体；动效 ≤200ms 且可关。
- **布局**：左侧模块导航（可折叠）+ 中部主视图（浏览器视图 / 树视图 可切换或分屏）+ 右侧属性抽屉 + 底部状态栏（进度/队列/日志）。分栏可拖拽。
- **按钮层级**：primary（1 个/区域）、secondary、ghost、danger（仅删除）；工具栏按功能分组并加分隔线；危险操作颜色区分 + 二次确认。
- **状态完备**：空状态（引导首次采集）、骨架屏、加载中、失败可重试、无权限提示。
- **键盘**：全流程可键盘操作；常用快捷键可在设置中查看与自定义。
- **可访问性**：对比度 ≥ 4.5:1，焦点可见，图标配文字或 tooltip；最小窗口宽度约束下不破版。

## 6. 非功能需求

- **性能**：单站万级节点可流畅浏览；抓取吞吐可配（默认 5 并发）；内存与队列在长任务下稳定。
- **稳定性**：异常退出可恢复现场（队列 + 修正层持久化）；抓取任务可断点续爬。
- **跨平台**：macOS 优先，Windows / Linux 可用（内嵌浏览器同源）。
- **可测试**：采集内核可脱离界面单独跑（CLI/单测），便于回归。
- **可扩展**：数据契约（Node/Edge/Override）版本化，破坏性变更须升 `schemaVersion` 并附迁移说明。

## 7. 技术架构建议

- **分层**：`core/`（URL 规范化、去重、调度、队列、抓取器、解析器、存储）与 `ui/`（视图）解耦，通过事件总线/IPC 通信；`plugins/`（导出器、解析器、后处理器）以稳定接口接入。
- **选型**：Tauri（Rust 内核 + 前端框架）体积小、性能好；或 Electron/Node + Playwright（生态成熟、上手快）。采集内核与界面分离后，二者可后换。
- **存储**：SQLite 作主存储（节点/边/修正层/队列），素材走文件系统 + manifest。
- **命名一致性**：界面模块名 = 路由名 = 代码目录名，避免「界面叫 X、代码叫 Y」。

## 8. 我做的澄清与优化（原文含糊 / 易用性改进）

1. **树→图**：明确站点结构是图，界面树是投影，引入「自动层 + 人工修正层」，从根上解决错误归并与拖拽修改的可逆性。
2. **锚点歧义**：拆分为「页内 fragment」与「链接」，避免开发期各说各话。
3. **「贪心最大深度」量化**：补齐深度/页数/范围/收敛阈值，否则自动模式在真实站点上必然跑飞。
4. **「修改地址」语义未定**：定义为「修正采集目标 URL，旧记录保留为历史别名，可选重抓」，避免改了地址数据状态不明。
5. **手动采集载体未定**：补充内嵌浏览器（CDP）方案与点击捕获机制，这是手动模式能否成立的前提。
6. **回根识别依据**：明确用规范化 URL 比对，并给出失败兜底，防止「智能识别」变成黑盒。
7. **删除改为软删除 + 撤销**：树操作误删代价极高，必须可恢复。
8. **大树可用性**：补虚拟滚动、过滤、聚焦子树 —— 未提及却是万级节点的生死线。
9. **导出对象含糊**：定义三档数据（结构/原件/解析）与 `schemaVersion` + 稳定 `nodeId`，否则下游工具无法可靠引用。
10. **补合规与礼貌**：robots、限速、并发与凭据安全，既防封站也防法律风险。

## 9. 优先级切片

- **P0（可用闭环）**：URL 校验与建站、自动采集（深度/去重/限速）、树视图基础（展开/折叠/属性面板/隐藏地址）、JSON+CSV 导出。
- **P1（体验与掌控）**：手动引导采集、拖拽重挂 + 修正层 + 撤销、软删除与收纳卡片、SQLite 导出 + manifest、断点续爬。
- **P2（专业与扩展）**：规则模块、本地只读 API、站点差异对比、定时重爬、插件体系、sitemap 种子、深色模式。

**验收标准（示例）**：同一 URL 因带不同跟踪参数出现 N 次 → 树中只 1 个节点；同一 URL 被 2 个页面链接 → 父节点列表 2 条、树中按规则挂 1 处且可手动改挂；无 JS 站点与纯 JS 站点都能采到链接；导出 SQLite 用第三方工具能直接查询节点与边。
